# M3 carry-forward — distilled from the M1/M2 execution ledger

M1 and M2 closed on 2026-10-15 at `75cc56b` (merged to `master`). The plan's scratch workspace
(briefs, per-task reports, review packages, the full 39-ruling ledger) was deleted after the merge
because git history is the record; this file preserves what the *next* milestone needs from it.

## Blockers to scaling the promotion loop (fix these first)

1. **Generated per-TU headers are C++-flavoured.** `include/src/**/*.h` splice the tag bare
   (`_tag_SYS_SCF_WORK`), which is C++ syntax, so a promoted unit cannot `#include` one yet — the
   first unit did without it. A C-mode emitter is needed before the first include-bearing TU.
2. **`ddr diff` is not yet a working basis for the unit under edit.** It refuses a unit with no C
   source (exit 2, deliberate: the split compared against itself reported a score objdiff never
   computed), and for a *promoted* unit it under-reports (~99.17%) because the split's `jal`s stay
   unresolved while ours are resolved. G1 and the per-TU verdicts are the arbiters meanwhile.
3. **Per-TU flags are measured for one unit only** (`3.0-011126 -c -lang c -O3 -g`, from
   `sys_scf.c`). Four 3.0 builds match that unit's bytes; widen the sample with
   `python3 tools/toolchain/select_build.py --tu <name>` across the first dozen TUs before
   `TU_BUILDS` grows much further.
4. **The `.line` gate is strict by design.** Statements must land on the retail line numbers the
   oracle reports (`tools/oracle/dwarf1.py lines <VA> --table`), and a promoted unit's `.debug`
   and `.line` bytes must both match — the promotion rule.

## Evidence we do not have (reverse it, or invent it deliberately)

| missing | how it is obtained |
|---|---|
| function bodies (statements, expressions, control flow) | reversed from the disassembly per function; byte-identity is the proof, nothing is guessed silently |
| names for the ~3,180 library-region functions | pattern DB (67 matched so far), in-binary assert strings, public corpora, cross-build matching — see §3 |
| type tags for the 25 anonymous aggregates (`@anon0..24`) | the fields are named; the source was likely anonymous too — use usage evidence, never invent a tag |
| SDK-side type layouts (`ThreadParam` 0x30, `SemaParam` 0x18, `_sceDmaTag` 0x10, `sceImage` 0x18 …) | absent from our DWARF; recover from the sibling builds' DWARF (E3 US 185 names, retail US 204, Festival JP 220) |
| which header each type/global came from | not in DWARF (per-TU type sets only) — our `include/` layout is a deliberate, documented convention |
| macro/inline structure | inferred from the line tables and codegen; helpers become `static inline` |
| enum members | DWARF 1 keeps very few enumerations — derive from usage or invent with provenance |
| the original SDK library objects | unobtainable in practice; the library region therefore stays split assembly (a scope decision, not a gap to close) |

## Library region — the naming plan (M4)

Four complementary sources, all already located and licence-checked:
in-binary assert strings (`libpad: sceSifSetDma faild`, `sceGsSyncPath: …`), the 138-entry Ghidra
R5900 pattern DB (`ghidra-emotionengine-reloaded`), public symbol corpora
(`AshfordFamily/recvx-decomp` ~6,010 names with sizes, MIT; `LucasPicoli/god-hand-decomp`
6,917 + 40,215, MIT; `ps2dev/ps2sdk` AFL-2.0 for semantics), and cross-build matching across the
nine sibling DDR `mwldps2` dumps and seven ELFs we hold.

## Live deferred minors worth folding into M3's first cleanup

18 `.bss` objects keep spimdisasm labels rather than DWARF names (addresses correct, referenced by
no split); 46 size-less splits are `.word` blobs (byte-exact); `fetch.py` records objdiff's digest
without pinning it (no upstream checksum exists); `_install_wibo` ignores `override_url` when a
pinned wibo is installed; wibo is installed with `copy2` rather than staging+rename;
`_wibo_entry` records the release URL for a fallback-supplied binary; `probe.py`'s docstring claims
`PlayStation2` occurs nowhere in `mwccps2.exe` (it does — it is simply not emitted into a
compile-only object's `.comment`); two `g1` localisation tests derive their expectation with the
implementation's own rule; a reference image no manifest record names falls back to its own digest
(now behind `--allow-unpinned-reference`); `pinned_hash()` is order-dependent; `ddr.CHECKSUMS`
duplicates `g1.CHECKSUMS`.
